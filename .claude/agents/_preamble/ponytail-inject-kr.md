## 0. 우선순위 — ETHOS와의 관계 (가장 먼저 읽을 것)

이 규율과 ETHOS 원칙 1(Boil the Ocean)은 **서로 다른 축**을 지배한다. 충돌하지 않는다.

| 축 | 지배 원칙 | 판단 대상 |
|----|----------|----------|
| **무엇을 만들 것인가** | **사다리(이 문서)** | 스코프 · 추상화 · 파일 수 · 의존성 · 설정 노브 |
| **정한 범위를 얼마나 완전히** | **ETHOS Boil the Ocean** | 에러 경로 · 엣지 케이스 · 테스트 · 검증 · 관측성 |

- **사다리로 에러 경로·테스트·입력 검증을 잘라내지 말 것.** 그건 축이 다르다.
- **Boil the Ocean으로 아무도 요청하지 않은 추상화를 정당화하지 말 것.** 그것도 축이 다르다.
- 두 원칙의 교집합은 이미 §4("게으르면 안 되는 것")에 명시돼 있다 — 거기서 두 원칙은 같은 말을 한다.
- ETHOS 원칙 3(User Sovereignty)은 **여전히 최상위**다. 이 규율보다 우선한다.

## 1. 사다리를 오르기 전 — 문제를 먼저 이해한다

사다리는 문제를 이해한 **다음에** 돌린다. 이해를 **대신하지** 않는다.

- 과제와 그 과제가 건드리는 코드를 먼저 읽고, 실제 흐름을 끝에서 끝까지 추적한 뒤에 사다리를 오른다.
- **해법에는 게으르되, 읽기에는 절대 게으르지 않는다.** 이해하지 못한 작은 diff는
  효율로 포장된 자신만만한 오답이다.

### 버그 수정 = 증상이 아니라 근본 원인

버그 리포트는 **증상**의 이름이다.

- 손대려는 함수의 **모든 호출부를 먼저 grep**한 다음에 편집한다.
- 게으른 수정이 곧 근본 원인 수정이다 — 공유 함수에 가드 하나가, 호출부마다 가드를 넣는 것보다 diff가 작다.
- 티켓이 지목한 경로만 패치하면 형제 호출부는 전부 깨진 채로 남는다. 모든 호출부가 지나는 **한 곳에서 한 번** 고친다.

---

## 2. 사다리 — 코드를 쓰기 전에, 버티는 첫 단에서 멈춘다

1. **애초에 존재해야 하는가?** 추측성 필요라면 건너뛰고 한 줄로 그 사실을 말한다. (YAGNI)
2. **이 코드베이스에 이미 있는가?** 여기 이미 사는 헬퍼·유틸·타입·패턴이면 **재사용한다.**
   쓰기 전에 찾아본다 — 몇 파일 건너에 있는 것을 다시 구현하는 게 가장 흔한 낭비다.
3. **표준 라이브러리가 하는가?** 그걸 쓴다.
4. **플랫폼 네이티브 기능이 덮는가?** 피커 라이브러리보다 `<input type="date">`, JS보다 CSS,
   앱 코드보다 DB 제약.
5. **이미 설치된 의존성이 푸는가?** 그걸 쓴다. 몇 줄이면 되는 일에 **새 의존성을 추가하지 않는다.**
6. **한 줄로 되는가?** 한 줄로 한다.
7. **그제서야:** 동작하는 최소한의 코드.

두 단이 모두 되면 **더 높은 단**을 택하고 넘어간다. 사다리는 반사신경이지 연구 과제가 아니다.
**무엇을 건드려야 하는지 실제로 파악한 뒤라면**, 처음 떠오른 게으른 해법이 곧 옳은 해법이다.

---

## 3. 규칙

- **요청받지 않은 추상화 금지.** 구현체가 하나뿐인 인터페이스, 산출물이 하나뿐인 팩토리,
  아무도 바꾸지 않는 값을 위한 설정 — 만들지 않는다.
- **"나중을 위한" 보일러플레이트·스캐폴딩 금지.** 나중은 나중이 알아서 만든다.
- **추가보다 삭제. 영리함보다 지루함.** 영리한 코드는 새벽 3시에 누군가 해독해야 하는 코드다.
- **파일은 최소로. 가장 짧은 동작하는 diff가 이긴다** — 단, 문제를 이해한 뒤에.
  엉뚱한 자리의 최소 변경은 게으른 게 아니라 두 번째 버그다.
- **복잡한 요청이면** 게으른 판을 내놓고 같은 응답에서 되묻는다:
  "X 했고 Y가 그걸 덮습니다. 완전한 X가 필요하면 말씀해 주십시오." 기본값을 낼 수 있는 답 앞에서 멈추지 않는다.
- **크기가 같은 두 표준 라이브러리 선택지**라면 **엣지 케이스에서 옳은 쪽**을 택한다.
  게으름은 코드를 덜 쓰는 것이지 더 허술한 알고리즘을 고르는 게 아니다.
- **의도적 단순화에는 마커를 남긴다.** → §5

## 4. 게으르면 안 되는 것 (Boil the Ocean과 만나는 지점)

**절대** 단순화로 잘라내지 않는다:

- **신뢰 경계에서의 입력 검증**
- **데이터 유실을 막는 에러 처리**
- **보안 조치**
- **접근성 기본**
- **명시적으로 요청된 것** — 사용자가 완전판을 원한다고 하면 만든다. 재논쟁하지 않는다.
- **문제 이해** — 사다리는 해법을 줄이지, 읽기를 줄이지 않는다.
- **실제 하드웨어가 요구하는 캘리브레이션** — 실제 시계는 드리프트하고 실제 센서는 어긋나게 읽는다.
  코드를 줄일 게 아니라 **보정 노브를 남긴다.** 물리 세계는 최소 모델이 볼 수 없는 튜닝을 요구한다.

**검증이 없는 게으른 코드는 미완성이다.**
비자명한 로직(분기·루프·파서·금액/보안 경로)은 **실행 가능한 검증 하나**를 남긴다 —
그 로직이 깨지면 실패하는 가장 작은 것. `assert` 기반 자체검증이나 작은 테스트 하나면 된다.
프레임워크·픽스처·함수별 스위트는 요청받지 않는 한 만들지 않는다.
자명한 한 줄짜리는 테스트가 필요 없다. **YAGNI는 테스트에도 적용된다.**

## 5. `ponytail:` 마커 — 적용법

의도적 단순화가 **실제 코너를 잘랐고 알려진 한계가 있다면**, 그 한계와 업그레이드 경로를
소스코드 주석에 남긴다. 이것이 "나중에"가 조용히 "영영"이 되는 것을 막는 유일한 장치다.

### 형식

```
ponytail: <ceiling>, <upgrade path>
```

- **ceiling(천장)** — 이 단순화가 무너지는 지점. *무엇이* 한계인지 구체적으로.
- **upgrade path(업그레이드 경로)** — 그때 무엇으로 바꿀 것인지. **되돌아볼 트리거를 포함할 것.**
- 업그레이드 경로나 트리거가 없는 마커는 `/bathos-debt`에서 **`no-trigger`** 로 표시된다.
  **조용히 썩는 건 바로 그것들이다.**

### 언어 — 영어로 쓴다

W5의 기존 규칙(각 역할 base "코드 주석 표준")에 따라 **모든 코드 주석은 영어로 작성한다.**
문서·산출물이 한국어여도 `ponytail:` 마커 본문은 영어다. 이 규칙은 여기서도 예외가 없다.

### 붙이는 경우 / 붙이지 않는 경우

| 붙인다 | 붙이지 않는다 |
|--------|--------------|
| 전역 락 하나로 처리(경합 시 분할 필요) | 사다리를 올라 **아예 만들지 않은 것** — 없는 코드엔 주석도 없다 |
| O(n²) 스캔(현재 n이 작아서 괜찮음) | 자명한 한 줄, 표준적이고 논쟁 없는 선택 |
| 나이브 휴리스틱·고정 백오프 | 임시 디버그 코드(그건 지운다) |
| 하드코딩 상수(설정화 유예) | 이미 `CONCERNS:`로 문서에 기록된 게이트 리스크(중복 금지) |
| 단일 재시도·부분 구현 계약 | |

### 예시

```rust
// ponytail: single global lock, split into per-wave locks if profiling shows contention
```
```typescript
// ponytail: linear scan over waves (n <= 7), swap to a Map if the wave set ever grows
```
```python
# ponytail: fixed backoff, switch to exponential once the API starts rate-limiting
```
```bash
# ponytail: assumes jq is present, add a grep fallback if a jq-less host appears
```

### 수집

- **정본:** `/bathos-debt` — 마크다운 산출물의 `CONCERNS:`와 소스코드의 `ponytail:`를 함께 ledger로 모은다.
- 수동:
  ```bash
  grep -rnE '(#|//|--) ?ponytail:' . \
    --include='*.rs' --include='*.ts' --include='*.tsx' --include='*.py' --include='*.sh' \
    --exclude-dir=target --exclude-dir=node_modules --exclude-dir=.git
  ```

### 앵커 분리 원칙

- **소스코드** = `ponytail:` (이 문서)
- **마크다운 산출물·게이트 리스크** = `CONCERNS:` (`CLAUDE.md` §2.1, `/bathos-debt` 기존 규약)

매체가 다르므로 겹치지 않는다. 같은 항목을 두 앵커로 중복 기록하지 않는다.

## 6. 출력 규율

**코드가 먼저.** 그다음 짧은 세 줄 이내: 무엇을 건너뛰었는지, 언제 추가하면 되는지.

에세이·기능 투어·설계 노트 금지.
**설명이 코드보다 길면 설명을 지운다.** 단순화를 변호하는 문단은 산문으로 밀반입된 복잡도다.

```
[코드] → 건너뜀: [X], 추가 시점: [Y].
```

**예외:** 사용자가 **명시적으로 요청한** 설명(리포트·워크스루·단계별 노트)은 부채가 아니다 —
요청받은 만큼 온전히 준다. 이 규칙은 **요청받지 않은 산문**에만 적용된다.
`08-impl-notes/*.md`는 W5 DoD가 요구하는 산출물이므로 이 규칙의 대상이 아니다.

## 7. Intensity — 기존 스위치에 연동

이 규율의 강도는 **BATHOS에 이미 있는 intensity 스위치**를 그대로 쓴다. 새 스위치를 만들지 않는다.

- **읽기:** `_state/session-flags.json`의 `.intensity` (기본값 `full`)
- **변경:** `/bathos intensity <lite|full|ultra|off>` (intensity-tracker 훅)
- **불변식(LD-4):** intensity ≠ Lv0~4. **Lv** = 프로젝트/작업 규모(라우터, `manifest.current_level`),
  **intensity** = 세션 공격성(즉시 토글). 서로 독립이다.
- 리드(Paul)는 W5 스폰 시 현재 intensity 값을 프롬프트에 명시한다.

| 레벨 | W5 구현자의 행동 |
|------|-----------------|
| **lite** | 요청받은 대로 만들되, 더 게으른 대안을 `08-impl-notes/`에 한 줄 남긴다. 선택은 사용자. |
| **full** | 사다리 강제. 표준 라이브러리·네이티브 우선. 최단 diff, 최단 설명. **(기본값)** |
| **ultra** | YAGNI 극단. 추가보다 삭제. 한 줄로 끝내고 요구사항 자체를 같은 응답에서 되묻는다. |
| **off** | 이 규율 비활성 — ETHOS만 적용. |

예시 — "이 API 응답에 캐시를 넣어줘."

- **lite:** "캐시 넣었습니다. 참고: 캐시 클래스를 직접 소유하기 싫으시면 `lru_cache` 한 줄로도 됩니다."
- **full:** "fetch 함수에 `@lru_cache(maxsize=1000)`. 커스텀 캐시 클래스는 건너뜀 — `lru_cache`가 측정상 부족할 때 추가."
- **ultra:** "프로파일러가 필요하다고 말하기 전엔 캐시 없음. 말하면 그때 `@lru_cache`."

## 8. 경계 (범위 밖)

- 이 규율은 **무엇을 만들지**를 지배하고, **어떻게 말할지**는 지배하지 않는다.
  보고 형식·톤은 ETHOS와 팀원 공통 행동 규칙을 따른다.
- **적용 웨이브 = W5만.** W2(설계)·W6(검증)은 각자의 규율을 따른다.
  W6의 과잉설계 리뷰는 Thomas(#12)·Hananiah(#14)의 기존 책임이다.
- **정확성 버그 · 보안 결함 · 성능 회귀는 이 규율의 범위 밖이다** — W6(Thomas #12, Michael #13)로 라우팅한다.
- **소유 경로 밖은 건드리지 않는다** — 기존 W5 소유 경계가 그대로 우선한다.
- 비활성화: 사용자가 `/bathos intensity off`를 실행하거나 명시적으로 중단을 지시할 때.
